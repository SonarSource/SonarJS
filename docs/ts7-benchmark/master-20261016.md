## TS6-free IPC experiment and dependency boundary

The experiment temporarily quarantines every installed package whose actual
identity is TypeScript below version 7, including the TS6 alias and nested TS5
compiler, before starting fresh real IPC workers. `NODE_PATH` and `NODE_OPTIONS`
are cleared. A preload guard rejects classic compiler implementations using the
shared identity policy, including absolute imports outside `node_modules`.
Every attempted worker records module-resolution attempts and loaded compiler
implementations. Both package directories are restored in `finally`; package
manifest hashes are verified after restoration.

All 59 attempts end with the same missing `typescript-classic` startup error.
All 59 audits have an empty loaded-compilers list. This verifies there was no
silent fallback in these failed startup attempts; because no analysis starts,
it cannot demonstrate a working TS6-free implementation or prove all later
native paths are independent of classic utilities. The current IPC provider
intentionally combines TS7 semantic programs/checkers with TS6 syntax, config,
flags and host utilities. The dependency must be replaced inside the abstraction
before a genuinely TS6-free successful run is possible. No duration is assigned
zero and the previous IPC timings remain explicitly hybrid measurements.

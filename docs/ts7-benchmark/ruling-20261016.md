# Full ruling corpus TS7 benchmark, 16 October 2026

All **59 active ruling projects** were attempted with TS6, TS7 IPC, WASM syscall
and WASM direct: **236 fresh workers, one round**. TS6 completed every project;
the three native variants each aborted five projects. Of the 54 projects whose
pipelines completed on every provider, **51 pass the validity gate and 34 also
match selected inputs and full normalized diagnostics**. Full-suite parity fails.

TS7 IPC is **2.142×** TS6 across the 51 valid projects, with differing results
included. Vitest is the largest regression: **71.266 s versus 439.423 s (6.17×)**,
with 81 additional findings. On the 34 strictly comparable projects, IPC is
**1.319×** TS6. Neither number establishes a full-suite equivalent-output result.
These are single observations, not medians or evidence of run-to-run stability.

This extends [PR #8184](https://github.com/SonarSource/SonarJS/pull/8184) under
[JS-2643](https://sonarsource.atlassian.net/browse/JS-2643).
**No rules or rule helpers changed in this follow-up.**

## Failures and compiler routing

Five projects abort only on native providers:

- it-tools: diagnostic 18002, an empty artificial `files` config during public
  `createProgram([])` construction.
- Joust, postgraphql and rxjs: diagnostic 5023, unknown compiler option
  `suppressImplicitAnyIndexErrors`. RxJS aborts after partial processing.
- knockout: diagnostic 6046, rejected legacy `module: umd` value.

Three further projects fail the strict validity gate on every provider:

- bulma: 11 Sass files fail with `LINTER_INITIALIZATION` / missing node source or
  undefined parser input.
- vuetify: the same Sass error class in VBottomSheet.sass, alongside native
  diagnostic/program-selection differences.
- courselit: no inputs in packages/rich-text/tsconfig.json. Production recovers
  and all 273 files / 5,689 findings match, but programCreation.failed is one;
  the benchmark deliberately keeps the failure visible.

No fixture configs or compiler semantics were changed to mask these failures.
The inactive `eslint` registry entry has no active ruling test and is excluded.
No worker timed out. The three already-failed RxJS processes retained a production
progress timer after saving their failure reports; they were manually terminated,
with `forced-exit.json` evidence and SIGTERM recorded. Their invalid worker wall
times are excluded. No accepted timing was interrupted. The post-run tooling now
exits failed workers after saving reports and closing compiler resources.

All **209 valid workers** verified one shared owned facade and SonarJS plus
typescript-eslint routing. All **221 workers whose pipelines reached the routing
check**, including shared-error cases, passed it. The 15 aborted native workers
cannot claim this post-analysis check. Existing runtime/bundle guards and the
production-import audit continue enforcing the shared boundary. This checks the
exercised dependency graph; no successful worker uses a private benchmark compiler
construction path.

## Reusable tooling and reproduction

`npm run ts7:ruling` supports `list`, `run` and `report`, project/backend subsets,
resumption and detailed result comparisons. The ruling tests and runner share
`createRulingProject`, so project metadata and rule configuration have one owner.
The provider registry/order is shared with the original single-project benchmark.
The runner uses production `initFileStores` + `analyzeProject`, covering discovery,
MAIN/TEST roles, exclusions, configured/orphan programs, Vue/HTML/YAML extraction,
CSS and normal production cleanup. It does not include the Java scanner or IDE.

Measured command (run from the benchmark worktree):

```sh
SONARJS_TS7_WASM=/Users/victor/projects/workspaces/SonarJS/ts7-benchmark/tools/ts7-benchmark/out/wasm \
node tools/ts7-benchmark/ruling.mjs run \
  --corpus /Users/victor/projects/jsts-test-sources \
  --runs 1 --output tools/ts7-benchmark/out/ruling-all-20261016
```

For a new run, choose a fresh output directory. The default is three rounds; eight
balance positions and reversed backend order for four providers. Workers execute
sequentially, each with an 8 GiB JS heap and a ten-minute timeout. Backend positions
rotate across projects. OS filesystem caches remain warm and uncontrolled.
No tests, builds or other benchmark jobs ran during accepted measurements.

```sh
npm run ts7:ruling -- list
# Example future run; SONARJS_TS7_WASM must name a revision-matched artifact.
npm run ts7:ruling -- run --corpus /Users/victor/projects/jsts-test-sources --runs 3 --output tools/ts7-benchmark/out/ruling-repeat
npm run ts7:ruling -- report --output tools/ts7-benchmark/out/ruling-all-20261016 --details
```

Add `--projects ag-grid,vitest` or `--backends ts6,ts7` for a targeted run.
`--resume` requires the same options and unchanged source/corpus/provider hashes;
completed failures are retained. Interrupted/unfinalized attempts are archived
before rerunning. Reports require recorded process completion. Rich differences
are computed outside the timed path, one project at a time. Aggregation retains
field hashes to bound memory and provides common and pairwise cohorts so one
provider's failure cannot hide another provider's regression. See the
[tooling guide](../../tools/ts7-benchmark/README.md#complete-ruling-suite).
